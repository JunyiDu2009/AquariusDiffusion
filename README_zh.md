# AquariusDiffusion

**原生低比特（NLT）扩散模型系列** —— 权重自第 0 步起就活在量化空间 `{−s, 0, +s}` 里，
而不是"先用 fp16 训好、再压缩"。

```
AquariusDiffusion/
└── AquariusImage/                        图像扩散子系列
    └── AquariusTerimage/                 三值文生图  ← 已发布
        ├── README.md / README_zh.md      模型主页（中英双语，含全部细节）
        ├── code/ · docs/ · figures/      代码、技术报告（中英）、报告配图
        └── portable/ · text_encoder/ · VAE/   Release 权重文件的落位目录
```

## 模型

| 模型 | 量化器 | 状态 |
|---|---|---|
| [**Aquarius Terimage**](AquariusImage/AquariusTerimage/) | 三值 `{−s, 0, +s}`，每 128 权重一个 fp16 尺度 + STE | **已发布** —— 558,347,012 参数打包成单文件 152.99 MB（2.192 bpw），三值→int4 融合内核逐位精确 |
| Aquarius Binimage | 二值 `{−s, +s}` | **未训练** —— 算力经费不足（报告 §7.1）。无权重、无样例。 |

## 从这里开始

- **模型主页 / 怎么跑：** [`AquariusImage/AquariusTerimage/README.md`](AquariusImage/AquariusTerimage/README.md)
- **权重：** 在本仓库的 **Releases** 页（三个文件）。int4 运行时内核会在**载入时按你的设备**从
  base-3 母版重建，因此不随包发布 CUDA 专用预建件。
- **技术报告**（中英，PDF + Markdown）：[`docs/`](AquariusImage/AquariusTerimage/docs/)
- **一句话结论（诚实版）：** 原生低比特训练与低比特融合内核推理都已在真实硬件上端到端验证可行；
  但在当前数据规模下模型**质量未达到可用发布水平**，饱和证据在报告中如实记录而非回避。
